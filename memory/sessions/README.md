# 会话记录

用户和代理在聊天界面上能看到的内容放在这里，随仓库提交到 Git。一次会话一个文件，多轮问答都追加在这个文件里。

## 路径

`memory/sessions/YYYY/MM/YYYY-MM-DD-短标题.md`

短标题用英文小写和连字符，日期与 YAML 里的 `date` 一致。`session` 用来识别同一次会话。已有这个标识就继续往该文件追加，不要另建文件。

## 一条的写法

用时间点做标题，精确到毫秒，不用 1、2、3 序号：

```markdown
## 2026-10-13 07:53:41.433 UTC

### 用户

用户这次说的话。

## 2026-10-13 07:53:41.433 UTC

### 思考

聊天界面上显示的模型思考。

## 2026-10-13 07:54:18.469 UTC

### 代理

代理这次的回复。

## 2026-10-13 07:54:18.469 UTC

### 工具

名称：run_terminal_cmd

参数：

结果：
```

按界面上的出现顺序保存用户原文、模型思考、代理回复，以及工具调用的名称、参数和结果。不改写成摘要、结论、上下文或下一步。时间用真实时间戳。某一条没有独立时间时，沿用其后最近一条真实时间，并保持原来的先后顺序。不要编造毫秒。密钥和令牌写入前要打码。

## 查找

新会话不因为这份说明就去读历史会话。用户明确要求参考，或确实有必要参考时，再用下面的方式查。

1. 先看 `INDEX.md`，按时间倒序。
2. 按会话标识找文件：`rg -n "^session: " memory/sessions`
3. 按原话或时间搜索：`rg -n "关键词" memory/sessions`

## 写入

1. 新会话：复制 `_template.md`，填 YAML 头和界面上的内容，把新行加到 `INDEX.md` 表格顶部。
2. 同一会话的后续内容：按时间追加到已有文件。
3. 与相关改动一起提交并推送。

## 按代理和模型查看提交

AI 生成的提交标题以 `[代理名/模型标识]` 开头，例如 `[Cursor/grok-4.7] 修复结算金额`。`git log --oneline` 就能直接看到。

说明末尾还有同样的两行：

```
Agent: 代理名
Model: 模型标识
```

按模型查看：`git log --grep='\[.*/grok-4.7\]'`

按代理查看：`git log --grep='\[Cursor/'`
